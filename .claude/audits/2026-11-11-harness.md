## Trouvailles

### 1. La revue périodique n'a jamais tourné : 50 PR mergées, aucune revue
**Pilier** : contraintes
**Preuve** :
- `CLAUDE.md` § Revue périodique : « Toutes les 20 pull requests mergées dans
  `main`, le harness et tout le code passent en revue. Une session lancée
  pour ça suit cette section ». Rien dans le harness ne lance cette session
  ni ne compte les PR : le seul endroit lu au merge est `revue-en-boucle`
  étape 7, qui n'en parle pas.
- `list_issues` étiquette `periodic-review` : 0 issue. 50 PR mergées depuis
  #6 (la PR qui a ajouté `.claude/`).
- Le propriétaire a fini par poser la question lui-même, chat du projet,
  2026-11-11 22:01 : « Est-ce que tu t'occuppes bien de DRY ? Est-ce que tu
  suis une arcitecture adapté du skill layered-rails ? ». Le verdict du fil
  « Vérifier DRY et l'architecture en couches » (22:03) : « DRY à moitié,
  pas de vraies couches (SQL dans 14 fichiers de pages) », exactement ce que
  `revue-architecture` devait trouver après la 20e PR.
**Remède** : contrôler — `revue-en-boucle` étape 7, juste après chaque merge,
compte les PR mergées depuis la dernière revue périodique et, à 20 ou plus,
le dit au propriétaire dans la réponse avec le nombre et la phrase pour la
lancer.
**Impact attendu** : PR mergées au-delà du seuil sans que la revue
périodique ait été signalée au propriétaire — base 30 (50 − 20) le
2026-11-11 — attendu 0 PR après le merge de cette passe sans signalement
dans le fil qui a mergé — contrôle le 2026-11-18 — sinon : un workflow
GitHub Actions sur `push` vers `main` qui ouvre lui-même l'issue
`periodic-review` à la 20e PR (proposé, pas écrit : `.github/` n'est pas
du harness que cette passe touche seule).
**Appliquée** : oui, commit « revue-en-boucle : signaler la revue périodique après le merge qui atteint 20 PR »

### 2. Le piège `ALTER TYPE … ADD VALUE` ne vit qu'en mémoire
**Pilier** : contexte
**Preuve** : `MEMORY.md`, ligne « Done: … Enum ADD VALUE + its use can't
share a migration batch (drizzle runs pending migrations in one
transaction) ». Le dépôt ne le dit nulle part (`grep -i "add value"` :
seulement `drizzle/0004_mouvements-de-caisse.sql`). Une session qui ajoute
une valeur d'enum lit `CLAUDE.md` § Base de données, pas cette ligne noyée
dans l'historique des PR (rencontré avec les mouvements de caisse, PR #21 et
la migration `0004`, d'après la mémoire ; je n'ai pas relu ce fil).
**Remède** : rapatrier — une phrase dans `CLAUDE.md` § Base de données.
**Impact attendu** : migrations rouges en CI ou au build Vercel pour une
valeur d'enum utilisée dans le même lot — base 1 (#21, 2026-11-10, d'après la mémoire) —
attendu 0 — contrôle le 2026-11-18 — sinon : un contrôle dans le check de
dérive des migrations de `ci.yml`.
**Appliquée** : oui, commit « CLAUDE.md : une valeur d'enum ajoutée ne sert pas dans le même lot de migrations »

### 3. La mémoire d'équipe raconte l'historique et garde des faits périmés
**Pilier** : entropie
**Preuve** :
- `MEMORY.md` fait 9 060 octets, chargés à chaque session : une vingtaine
  de lignes « Done PR #… (merged …) » qui répètent les titres de PR et le
  README (tri de l'inventaire, tuiles de caisse, recherche des tarifs…).
- Faux aujourd'hui : « PR #77 pending » (mergée le 2026-11-10) ; « he wants
  to KEEP the Vercel bot comments » (depuis #77 Vercel ne déploie plus les
  branches, et depuis #102 le lien est dans la description, plus aucun
  commentaire) ; `caillou-preferences.md` : « This overrides CLAUDE.md §
  Ouvrir une pull request (« Assigne la PR… ») until CLAUDE.md is updated »
  (`CLAUDE.md` dit l'inverse depuis #48).
**Remède** : supprimer — après le merge, réduire chaque ligne « Done » à ce
qui n'est pas dans git ni le README (actions que le propriétaire doit encore
faire, décisions prises en conversation), et corriger les trois faits
périmés.
**Impact attendu** : taille de `MEMORY.md` — base 9 060 octets le
2026-11-11 — attendu sous 4 000 — contrôle le 2026-11-18 — sinon : une
règle dans `CLAUDE.md` § Un fait, une place qui interdit l'historique de PR
en mémoire.
**Appliquée** : proposée, faite en mémoire après le merge (garde-fou : une
mémoire ne se vide qu'après le merge).
